# DealPilot — Test-Driven Development Plan
Status: Approved · Owner: CTO · Companion: `testing.md` (gates & process), `ci-cd.md` (where these run).

## 1. Philosophy

Tests are the executable spec of the doctrine. The invariants in `../architecture/system-design.md` §2.3 aren't documentation — each is a named test that fails if violated. Red → green → refactor is mandatory on `domain-core` and the verification pipeline; pragmatic elsewhere. We don't chase coverage; we chase **the inability to break a promise silently**.

## 2. Test Pyramid & Budgets

| Layer | Share (approx.) | Runtime budget (CI) |
|---|---|---|
| Unit (domain, pure) | 60% | < 90 s |
| Integration (repos, workflows, adapters) | 25% | < 8 min |
| Contract (API, activities, verifier vectors) | 8% | < 3 min |
| E2E (golden pipeline) | 5% | < 20 min (nightly full; smoke on merge) |
| Load/chaos/security | 2% | scheduled |

## 3. Unit Tests (domain core)

Every aggregate ships an invariant suite. Example — Claim status transitions (TS, vitest):

```ts
describe("Claim invariants", () => {
  it("cannot reach VERIFIED without tier-A evidence", () => {
    const claim = ClaimFixture.reported();
    const res = claim.adjudicate({
      status: "VERIFIED",
      evidence: [evidenceFixture({ tier: "B" })],
      rubric: RUBRIC_V3,
    });
    expect(res).toEqual(err(DomainError.RubricViolation("VERIFIED_REQUIRES_TIER_A")));
  });

  it("CONTRADICTED requires cited evidence on both sides", () => {
    const res = ClaimFixture.reported().adjudicate({
      status: "CONTRADICTED",
      evidence: [supporting()],       // only one side
      rubric: RUBRIC_V3,
    });
    expect(res.isErr()).toBe(true);
  });

  it("every failure path lands UNKNOWN (fail-closed)", () => {
    for (const failure of ALL_FAILURE_MODES) {
      expect(ClaimFixture.pending().onFailure(failure).status).toBe("UNKNOWN");
    }
  });
});
```

Valuation: `REFUSED` on material UNKNOWNs (table-driven over MaterialityPolicy versions). Memo: cannot `PUBLISHED` without `CitationCheckPassed` for the current revision hash. CreditLedger: balance = fold(events), never negative absent an authorized overdraft event.

## 4. Property-Based Tests (fast-check / hypothesis)

- **Ledger chain**: ∀ event sequences — `verify(chain(events)) === true`; flipping any byte in any event ⇒ verification fails at exactly that seq; appends never mutate prior hashes.
- **CreditLedger**: ∀ interleavings of grants/consumes — invariant holds; replay is order-stable.
- **Citation checker**: ∀ memos generated by the memo-grammar — checker never passes an uncited factual sentence (grammar labels ground truth).
- Canonical-JSON: ∀ payloads — `canon(parse(canon(x))) === canon(x)` (hash stability across languages — this property *is* the offline-verifier contract).

## 5. Integration Tests

Testcontainers (PG, Redis, Kafka/redpanda, LocalStack S3) + **Temporal test environment** (time-skipping): repos replay aggregates from real event rows; projectors rebuild read models from a seeded stream and match snapshots; a full verification workflow runs against the **model stub server** with recorded fixtures; outbox → Kafka delivery is exactly-once-effectively (idempotent consumer proof). Every RB-class failure mode (worker killed mid-activity, PG failover blip) has an integration test proving resumption.

## 6. Contract Tests

- **API**: OpenAPI 3.1 is source of truth; schemathesis fuzzes implementations against spec per build; generated SDKs run a consumer-driven suite (create→run→poll→memo) against a spec-pinned mock and nightly against staging.
- **Worker activities**: typed I/O schemas (`/packages/contracts`) — TS workflow and Python workers both validate against the same JSON Schema in CI (drift = red).
- **Offline verifier conformance vectors** (ADR-012): `/conformance/vectors/*.json` — canonical event streams + expected chain heads + tamper cases. Pipeline and the independently-implemented OSS verifier must both pass; **vectors are the contract**, shared code is forbidden. New event types require new vectors in the same PR.
- **Webhooks**: signature + retry semantics contract-tested against a recorder.

## 7. End-to-End (golden pipeline)

Nightly in staging: full golden corpora (200 RE deals + 120 CIMs) through the real pipeline (stub models by default; weekly live-model run within budget). Assertions: labeled claim statuses within tolerance bands, UNKNOWN precision/recall floors, valuation ranges/REFUSALs match labels, every memo passes citation check, ledger export verifies with the OSS binary. Merge-blocking smoke: 5-deal subset, < 8 min.

## 8. Load Tests (k6; targets from `testing.md` §5)

Read API 300 RPS sustained @ p95 < 300 ms; 500 concurrent verification runs (stubbed models — we're testing *our* system) with queue-age p95 < 60 s; webhook fan-out 50/s; 24 h soak weekly at 40% peak watching leaks/lag. Regressions > 10% vs baseline block release.

## 9. Chaos Testing

Scheduled (staging weekly, prod game-days quarterly): kill workers mid-activity → workflow resumes, no duplicate ledger events (idempotency proof); PG failover → writes recover < 60 s, chain intact; Kafka partition loss → outbox redelivers, projectors idempotent; **model-provider fault injection** (latency ×10, 5xx, garbage JSON) → routing fails over per RB-02, affected claims land UNKNOWN, zero fabrications; S3 CAS 503s → runs pause, fail-closed. Every chaos scenario maps to a runbook; a scenario without a runbook is a finding.

## 10. Security Testing

In CI: semgrep (custom rules: SQL-outside-repos, log-scrubber bypass, raw-doc-into-Composer imports), dependency + container scans, gitleaks, **cross-tenant probe suite** (attempts org-B reads with org-A creds across every endpoint — any pass is SEV-1-class red), **adversarial injection corpus** (ai-architecture §6.5) against current prompts/models. Nightly: ZAP baseline on staging. Annual: external pen test (scope priorities: TB2 sandbox, T-4 isolation).

## 11. Mutation Testing

Stryker (TS) + mutmut (py) on **verification pipeline, ledger, citation checker, credit ledger**: mutation score ≥ 80% required (report per PR touching those paths; full run nightly). Rationale: coverage proves execution, mutation proves *assertion* — on doctrine-critical code we pay the CI cost happily. Surviving mutants are triaged: kill with a test or document why equivalent.

## 13. Test Data Strategy

**Golden corpora** are versioned assets (DVC-style pointers → S3; PII-scrubbed, licensed for internal eval; labeling guide + double-labeling with adjudication for disagreements; version bump = eval baselines re-pinned deliberately). **Synthetic deal generator** (seeded, grammar-based) produces unlimited structurally-valid deals + labeled injection variants. Fixtures: factory pattern (`ClaimFixture.reported().withMateriality("blocking")`) — no shared mutable fixture files; builders over blobs. Prod data never enters tests (staging is synthetic-only by policy + scanner).

## 14. Mocking Strategy

Mock at **boundaries only**: model providers (stub server with recorded, seed-deterministic responses — the workhorse), external sources (adapter fakes per tier), Stripe (stripe-mock + recorded webhooks), time (Temporal test env / injected clock). **Never mock domain internals** — if a domain test needs a mock, the design is wrong; fix the design. HTTP recording (VCR-style) allowed for adapter development, committed cassettes scrubbed.

## 15. Coverage & Acceptance

Gates: **85% line+branch on `domain-core` and verification pipeline; 70% overall**; mutation ≥ 80% on §11 scope; coverage may never decrease on touched files (ratchet). Coverage is a floor, not a target — reviewers reject assertion-free "coverage tests" on sight. **Acceptance**: every PRD acceptance criterion (FR-x.y) maps to at least one named test (`@ac FR-6.1` annotations); the traceability matrix is generated in CI and attached to release notes — an unmapped AC blocks the release train (`testing.md` §3).
